# Falco Notes

## What Falco Does

Falco is a runtime security tool that watches activity occurring on a
Kubernetes node and looks for behavior that may indicate a security problem.

In K8s Sentinel, Falco runs as a DaemonSet, which means a Falco agent runs on
each Kubernetes node.

## eBPF Probe

This deployment uses Falco's `modern_ebpf` driver.

The eBPF probe allows Falco to observe events generated by the Linux kernel
without requiring a traditional kernel module. In our cluster, Falco
confirmed that it opened the syscall event source using the modern BPF probe.

The Falco logs showed:

```text
Opening 'syscall' source with modern BPF probe.
```

This confirms that the intended event collection mechanism is active.

## Syscall Events

Applications and containers interact with the Linux operating system through
system calls, or syscalls.

Examples include operations related to:

* Starting processes
* Opening files
* Reading files
* Writing files
* Executing programs
* Creating or modifying processes

Falco observes these events and enriches them with information about the
process, container, and Kubernetes workload.

## Rules Engine

Falco does not treat every syscall as a security alert.

Instead, events are evaluated against Falco rules. A rule describes behavior
that may indicate suspicious or dangerous activity.

For example, during our manual test we executed a shell inside the
`privileged-pod`.

Falco generated:

```text
Notice A shell was spawned in a container with an attached terminal
```

We also tested reading `/etc/shadow`, which generated:

```text
Warning Sensitive file opened for reading by non-trusted program
```

Falco also identified the Kubernetes context:

```text
k8s_pod_name=privileged-pod
k8s_ns_name=default
```

This is important because runtime events can be connected back to the
Kubernetes workload that generated them.

## Detection Flow

The basic flow in K8s Sentinel is:

```text
Container activity
       |
       v
Linux kernel syscall
       |
       v
Falco modern eBPF probe
       |
       v
Falco event processing
       |
       v
Falco rules engine
       |
       v
Security alert
```

## Day 3 Test Result

The Falco installation was tested by opening a shell inside the intentionally
vulnerable `privileged-pod`.

The test successfully generated Falco alerts.

This confirms that:

1. Falco is running on both Kubernetes nodes.
2. The modern eBPF driver is active.
3. Syscall events are being collected.
4. Falco rules are being evaluated.
5. Suspicious container activity generates alerts.
6. Falco can identify the Kubernetes pod associated with the event.

## Why This Matters for K8s Sentinel

Falco provides the runtime detection layer of K8s Sentinel.

Later stages of the project can consume these security events and use them to
trigger automated response and remediation actions.

The intended architecture is:

```text
Kubernetes workload
        |
        v
Runtime activity
        |
        v
      Falco
        |
        v
Detection event
        |
        v
K8s Sentinel
        |
        v
Automated remediation
```
